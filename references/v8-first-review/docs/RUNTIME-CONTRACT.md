# V8 — proposed runtime contract

The JSON in `assets/runtime-fixture.json` is a synthetic design fixture: 3 highways, 6 points, 5 segments, 20 lane records, and 5 activation records. It is not generated by Unreal and is not a complete traffic/navigation graph. The viewport and individual screen scenarios are larger illustrative examples, not the same compiled dataset.

## Data ownership

Landscape supplies point/segment geometry and source bindings. Nexus authoring supplies ownership, codes, lane-profile references, rule semantics, and activation payloads. A validated compiler will produce an immutable runtime snapshot. Catalog entries resolve at read/generation time and may be flattened only into derived runtime output, never back into authored descendants. Dynamic signals, reservations, occupancy, and agents belong to a separate mutable runtime store.

## Required record families

| Family | Required information |
|---|---|
| World/hierarchy | GUIDs, ownership, source fingerprints, schema version, selected config/profile references. |
| Highway | Point/segment references, lane profile, mesh-config reference, ConnectedHighwayIds. |
| Point | GUID, source binding, position, tangent/geometry relationships, junction classification, feature summaries. |
| Segment | Start/end IDs, tangents, samples/length, semantic lane-profile reference, owner highway. |
| Lane | Direction, width, speed, allowed classes, samples, predecessor/successor/lateral links, change intervals. |
| Junction connector | Incoming/outgoing lane GUIDs, maneuver, rule, control group, geometry/samples in real implementation. |
| Pedestrian network | Walkability, usable width, access flags, crossings, service entrances, signal references. |
| Traffic signal | Pole/head offsets, movement groups, controller links, conflict-aware timing definitions. |
| Crosswalk | Endpoints, span/depth, independent waiting points, pedestrian links, signal controller. |
| Bus Stop | Entry/stop/exit, waiting, boarding/alighting, lane relationship, shelter/base/indicator/seat slots and offsets. |
| Seat Group | Physical count, logical capacity, spacing, positions, rotations, interactions, optional grouping. |
| Parking | Rows/columns/gaps, spot dimensions, angle, bay transforms/IDs, access lanes, vehicle classes, component slots. |
| Generation manifest | Source and build IDs, fingerprints, output ownership, chunk membership, replacement policy. |
| Mutable runtime state | Parking leases/occupancy, seat reservations, signal state, logical agents, pooling/restoration rules. |

## Units and identity

The fixture labels positions in meters, rotations in degrees, and speeds in kilometers per hour. Real Unreal import/export must explicitly convert to its chosen canonical units rather than infer them. Every runtime entity uses a GUID independently from its human-readable code. The fixture uses deterministic UUIDs so repeated packaging retains the same IDs.

## Consumer boundary

A lane-change edge grants permission over a station interval; it does not certify the maneuver is safe. Real runtime consumers must check space, traffic conflicts, headway, vehicle capabilities, and current service availability. A lane-following visual or looping animation is not proof of pathfinding, collision avoidance, or route correctness.

## Future verification

Canonical graph validation must include all required turn connectors, geometry continuity, lane restrictions, service reachability, stale input rejection, serialization round-trips, and no-path results. Bus Stop, Parking, and Seat Group require separate fixtures. The small JSON subset demonstrates fields and valid referenced IDs, but not complete navigability.
